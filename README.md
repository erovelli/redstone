# Redstone UI

Drop-in UI components where every component is a working Minecraft redstone contraption, simulated by a zero-dependency redstone tick engine and drawn on a canvas.

```html
<script src="redstone-ui.js"></script>

<rs-navbar><a href="/">Home</a><a href="/docs">Docs</a></rs-navbar>
<form>
  <rs-toggle name="lights" checked>Lights</rs-toggle>
  <rs-button>Save</rs-button>
</form>
```

The contraption is the widget's state machine. A click is a player action (flip the lever, press the button); `checked` changes and `change` fires when the lamp lights, not when the pointer goes down. Every component is meant to be rebuildable block for block in Minecraft Java 1.21 under the rules contract in [docs/SPEC.md](docs/SPEC.md) section 3: real blocks only, power only from propagation, blocks moved only by pistons, timing only from redstone, and code acting on a sealed world only through a player's hand. Each component is form-associated where it makes sense, keyboard operable and announced to screen readers. [docs/AUDIT.md](docs/AUDIT.md) records how each one was checked against those rules and where it falls short.

## Quick start

Build once (`npm run build`), copy `dist/redstone-ui.js` next to your page, and add one script tag. It defines `window.Redstone` and every `<rs-*>` element, and injects the CSS:

```html
<script src="redstone-ui.js"></script>
```

Add `data-rs-no-style` to the tag and link `redstone-ui.css` yourself for a strict CSP. `--rs-block` sets the block size (12 to 48 px, default 24); `Redstone.config.sound = true` turns on synthesised block sounds; the `inspect` attribute shows any component in x-ray. Without the script, the markup inside each element stays usable HTML (links are links, content is readable).

To work on the library (Node 18+, no dependencies):

```
npm test                 # engine, every catalogue entry, the UI suites and the rules audit
npm run build            # dist/redstone-ui.js, dist/redstone-ui.css, dist/index.html (docs), dist/catalogue.html (workbench)
npm run test:browser     # Playwright smoke test of the components (skipped without Playwright)
node scripts/shot.js toggle --width 320 --dark      # screenshot one gallery section
node scripts/audit-rules.js                         # the full rules audit report
node scripts/export-commands.js ui-modal            # a Minecraft .mcfunction that rebuilds an entry
```

Open `dist/index.html` for the component gallery (live examples, snippets, attribute tables, deviations) and `dist/catalogue.html` for the contraption workbench.

## API

| `window.Redstone` | |
|---|---|
| `ui` | `define(tag, spec)`, `describe(tag)`, `clickStaysInside`, test helpers. See [docs/COMPONENTS.md](docs/COMPONENTS.md). |
| `engine` | The tick engine (`World`, `defineBlock`, `world.hand`, ...). See [docs/ENGINE.md](docs/ENGINE.md). |
| `catalogue` | Every contraption: `entries`, `get(id)`, `register(entry)`, `runTests(entry)`. |
| `render`, `textures` | The renderer and the texture atlas. |
| `config`, `version` | `{ sound }`, the package version. |

Every element exposes `element.contraption` (`{ world, io, entry, built, view, state }`). In Node, `require('redstone')` returns the catalogue (with `.engine`), `require('redstone/engine')` the engine and `require('redstone/ui')` the headless half of the UI core.

## Layout

```

src/blocks/*.js               extra block definitions, one per file, self-registering
src/contraptions/logic.js     builders for the workbench's logic, clock, signal and sensor demos
src/contraptions/pistondoor.js   the 2x2 piston door

src/textures.js               the texture atlas (vanilla texture names, original pixel art)
src/render.js                 models, views, inspect mode
src/ui/core.js                custom-element base: ticker, sleep, resize, inspect, a11y, forms, sound
src/ui/ui.css                 page-level CSS (per-component CSS sits next to each component)
src/ui/components/*.js        one <rs-*> element per file
src/index.js                  Node entry
pages/docs.html               the docs site (dist/index.html); pages/demos/*.html are its gallery sections
pages/catalogue.html, catalogue-app.js   the contraption workbench (dist/catalogue.html)
scripts/build.js              the build (plain Node, discovers files in load order)
scripts/audit-rules.js        the rules audit (static scan and instrumented worlds)

scripts/export-commands.js    Minecraft commands for a catalogue entry
scripts/shot.js, smoke.js     screenshot helper, browser smoke test
test/run.js                   catalogue tests + every test/**/*.test.js suite
```

## Engine simplifications

The engine targets Java 1.21 and is simpler than the game in a few documented ways (full list in [docs/ENGINE.md](docs/ENGINE.md)): one update pass per redstone tick in a fixed order, so Java's block-event order, 0-ticks and BUD states are not modelled; quasi-connectivity is level-triggered; pistons move their blocks within the tick; entities are points; sculk strength is approximated; flowing water is not simulated (strict worlds refuse uncontained water). A design must not depend on behaviour the engine cannot model; where one might (the navbar's pearl launch), its entry says so.

## CI

`.github/workflows/ci.yml` runs `npm test` and `npm run build` on every push and pull request, and deploys `dist/` (the docs as `index.html`, the workbench as `catalogue.html`) to GitHub Pages from `main`.
