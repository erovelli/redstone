Redstoneui

UI components that are working redstone contraptions. A click flips a lever or presses a button; the element's state changes when the lamp lights, the door is clear, or the pearl hits its target. Every machine can be rebuilt block for block in Minecraft Java 1.21.

Getting started

  1. Add one script tag. It defines every <rs-*> element and injects its CSS. No build step and no dependencies.
    html
    <script src="redstone-ui.js"></script>
  2. Write ordinary-looking HTML. Text inside an element is its label, written on the machine's signs. Without the script it is still readable HTML.
    html
    <form>
  <rs-toggle name="lights" checked>Lights</rs-toggle>
  <rs-button>Save</rs-button>
</form>
  3. Listen as you would to native elements. Events fire when the contraption's output changes, never on the raw click.
    js
    document.querySelector('rs-toggle').addEventListener('change', e => {
  console.log(e.target.checked);   // true once the lamp is lit
});
  4. Size and options. --rs-block sets the block size (12 to 48 px, default 24) and an element shrinks to fit narrow containers. Redstone.config.sound = true turns on block sounds (off by default, never before a user gesture, never with reduced motion). Put data-rs-no-style on the script tag and link redstone-ui.css yourself if you need a strict CSP. Add inspect to any element to x-ray it.

contract

The rules

Target: Minecraft Java Edition 1.21. A contraption that honours all six rules is strict. One that cannot yet lists each gap, and the list is shown with the component.

  1. Real blocks only. Vanilla blocks with their vanilla movability, conductivity and stickiness. No invented wall or floor blocks.
  2. Power comes only from propagation. No wiring links, and no code sets a lamp, torch or piston after the build. The built state is the state the engine settles into.
  3. Blocks move only because a powered piston moved them. Code never moves blocks in a sealed world.
  4. Time comes from redstone. Repeaters, torches, comparators and observers sequence the machine. JavaScript watches the world; it never drives it.
  5. The only thing code does to a world is a player action, through world.hand: flip a lever, press a button, step on a plate, fill a barrel, turn a lectern page, write on a sign. Pointer and keyboard input map to these.
  6. Nothing is hidden by fiat. Helper blocks are out of sight only because other blocks are in front of them. Every component looks right in inspect (x-ray) mode.

Text lives on signs and lecterns, or behind real openings. Motion is the engine's motion, one piston stroke per tick. With reduced motion the world settles at once and the final frame is drawn; the state still comes from the contraption.

core

How a component works

pointer or key→world.hand action→redstone ticks→output block changes→property, attribute, event

Every element shares one base. It builds the contraption from its catalogue entry, draws it at --rs-block pixels per block, and puts real focusable controls over the blocks a player can use. One 100 ms ticker serves the whole page and skips worlds that are quiet or off-screen. Light-DOM content meets the blocks in two ways: text on a sign, or content shown through an opening the machine makes.

Content through an opening

<rs-demo-hatch>test element

Two sticky pistons hold planks covers in a stone frame. Flip the lever off and the pistons pull the covers down; the slotted content is shown only once both cells of the opening are empty, and hidden again before the covers come back.
